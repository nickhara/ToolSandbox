# Repair-DfsTargetsFromCsv — Recovery Runbook

## Purpose

`Repair-DfsTargetsFromCsv.ps1` restores DFS folder targets that were incorrectly removed by
`Remove-InactiveDfsTargetsV2.ps1`. It reads the removals CSV produced by that script, validates
whether each removed target's UNC path is still unreachable, and if it is reachable, it re-adds reachable targets to the
DFS namespace.

---

## Prerequisites

| Requirement | Details |
|---|---|
| **PowerShell 7+** | Required for `ForEach-Object -Parallel`. The script will exit with a clear error on older versions. |
| **DFSN module** | The DFS Namespaces PowerShell module must be installed (`New-DfsnFolder`, `New-DfsnFolderTarget`, `Get-DfsnFolder`). |
| **Permissions** | The executing account must have write access to the DFS namespace being repaired. |
| **Removals CSV** | A CSV from `Remove-InactiveDfsTargetsV2.ps1` with columns: `Timestamp`, `DfsServer`, `LinkPath`, `TargetPath`, `Reason`, `Status`. |

---

## Quick Start

```powershell
# 1. Dry run — preview what would be restored (no changes made)
.\Repair-DfsTargetsFromCsv.ps1 -RemovalsCsvPath ".\logs\removals_20260328_100107.csv" -WhatIf

# 2. Execute the repair
.\Repair-DfsTargetsFromCsv.ps1 -RemovalsCsvPath ".\logs\removals_20260328_100107.csv"

# 3. Execute with higher parallelism
.\Repair-DfsTargetsFromCsv.ps1 -RemovalsCsvPath ".\logs\removals_20260328_100107.csv" -ThrottleLimit 32
```

---

## Parameters

| Parameter | Required | Default | Description |
|---|---|---|---|
| `-RemovalsCsvPath` | Yes | — | Path to the removals CSV generated by `Remove-InactiveDfsTargetsV2.ps1`. |
| `-ReachabilityTimeoutSeconds` | No | `15` | Timeout in seconds for each UNC path reachability check. Increase on slow networks. |
| `-ThrottleLimit` | No | `16` | Maximum number of concurrent parallel operations. Higher values speed up processing but increase DFS server and network load. |
| `-ProgressFile` | No | `logs\repair_progress_<csv-basename>.json` | Path to the JSON progress file for resumable runs. |
| `-ResetProgress` | No | `$false` | Deletes the progress file before starting, forcing a full re-scan of all rows. |
| `-LogFilePath` | No | `logs\Repair-DfsTargetsFromCsv_<timestamp>.log` | Path for the transcript log. |
| `-WhatIf` | No | `$false` | Preview mode — shows what would be restored without making any changes. |

## High-Level Design

### Processing Pipeline

```
┌──────────────────────────────────────────────────────────────┐
│  1. LOAD & VALIDATE                                          │
│     Import CSV → validate columns → filter Status="Removed"  │
│     Load progress file → skip already-completed rows         │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│  2. PARALLEL PROCESSING  (ForEach-Object -Parallel)          │
│     Up to ThrottleLimit concurrent workers, each:            │
│                                                              │
│     ┌─ Reachability Check ─────────────────────────┐         │
│     │  Test-Path with timeout on the UNC TargetPath │         │
│     └──────────────┬──────────────────┬────────────┘         │
│              Reachable           Unreachable                 │
│                  │                    │                       │
│     ┌────────────▼──────────┐    Record as                   │
│     │  DFS Link Check       │    "Unreachable"               │
│     │  Get-DfsnFolder       │    and skip                    │
│     └─────┬───────────┬─────┘                                │
│      Link exists   Link gone                                 │
│           │            │                                     │
│  New-DfsnFolderTarget  New-DfsnFolder                        │
│  (re-add target)       (recreate link + target)              │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│  3. POST-PROCESSING                                          │
│     Save progress file (batch)                               │
│     Write recovery report CSV                                │
│     Write updated removals CSV (with new Status values)      │
│     Print summary                                            │
└──────────────────────────────────────────────────────────────┘
```

### Parallel Architecture

The script uses `ForEach-Object -Parallel` (PowerShell 7) to process all removed targets
concurrently, up to the `-ThrottleLimit`. Thread safety is achieved through:

| Collection | Type | Purpose |
|---|---|---|
| `$sharedCounters` | `[hashtable]::Synchronized` | Atomic counter updates via `[Interlocked]::Increment` (Reachable, Unreachable, Restored, Errors, etc.) |
| `$repairOutcomes` | `ConcurrentDictionary<string,string>` | Maps `LinkPath\|TargetPath` → outcome status for updating the CSV |
| `$newCompletedRows` | `ConcurrentDictionary<string,string>` | Tracks newly completed rows for progress file merge |
| `$recoveryRecords` | `ConcurrentBag<PSObject>` | Collects recovery report entries for batch CSV write |

A background `Start-ThreadJob` monitors the shared counters every 2 seconds, driving a
`Write-Progress` bar and periodically flushing the progress file (every 30 completions).

### Progress Tracking & Restartability

The script is designed to be safely interrupted and restarted:

1. **Progress file** — A JSON file tracks every completed row (keyed by `LinkPath|TargetPath`).
2. **On restart** — The script loads the progress file, skips already-completed rows, and
   processes only the remaining ones.
3. **Periodic flush** — During parallel execution, the background monitor job flushes progress
   to disk every 30 completions. This limits data loss if the script is killed mid-run.
4. **Final save** — After all parallel workers finish, a final batch write ensures every
   completed row is persisted.
5. **`-ResetProgress`** — Deletes the progress file to force a clean re-scan of all rows.

## Output Files

The script produces several output files, all created alongside the script or in subdirectories:

| File | Location | Description |
|---|---|---|
| **Transcript log** | `logs\Repair-DfsTargetsFromCsv_<timestamp>.log` | Full console transcript of the run. |
| **Recovery report** | `results\recovery_all_<timestamp>.csv` | CSV of all targets that were restored (or would be restored in WhatIf mode). Columns: `Timestamp`, `DfsServer`, `LinkPath`, `TargetPath`, `Action`, `Status`. |
| **Updated removals CSV** | `<original-csv-name>_updated.csv` | Copy of the input CSV with the `Status` column updated to reflect repair outcomes. |
| **Progress file** | `logs\repair_progress_<csv-basename>.json` | JSON checkpoint file for resumable runs. |

### Updated Status Values

The updated removals CSV replaces `Status="Removed"` with one of:

| Status | Meaning |
|---|---|
| `Restored` | Target was successfully re-added to the DFS namespace. |
| `WouldRestore` | Target is reachable and would be restored (seen in `-WhatIf` mode). |
| `Unreachable` | Target's UNC path was confirmed unreachable — the original removal was correct. |
| `RepairFailed` | Target is reachable but the DFS repair operation failed (see logs for details). |

## Example Workflow

```powershell
# Step 1: Dry run to see what would happen
.\Repair-DfsTargetsFromCsv.ps1 `
    -RemovalsCsvPath ".\logs\removals_20260328_100107.csv" `
    -WhatIf

# Step 2: Review the updated CSV to confirm expectations
Import-Csv ".\logs\removals_20260328_100107_updated.csv" |
    Group-Object Status | Select-Object Name, Count

# Step 3: Execute the actual repair
.\Repair-DfsTargetsFromCsv.ps1 `
    -RemovalsCsvPath ".\logs\removals_20260328_100107.csv"

# Step 4: If interrupted, simply re-run — it resumes from where it left off
.\Repair-DfsTargetsFromCsv.ps1 `
    -RemovalsCsvPath ".\logs\removals_20260328_100107.csv"

# Step 5: To force a full re-scan (e.g., network issues resolved)
.\Repair-DfsTargetsFromCsv.ps1 `
    -RemovalsCsvPath ".\logs\removals_20260328_100107.csv" `
    -ResetProgress
```

## Tuning Guide

| Scenario | Recommendation |
|---|---|
| Large CSV (1000+ rows), fast network | Increase `-ThrottleLimit` to 32–64 |
| Slow or congested network | Decrease `-ThrottleLimit` to 8, increase `-ReachabilityTimeoutSeconds` to 30 |
| Many targets share the same DFS link | Lower `-ThrottleLimit` to reduce concurrent DFS writes to the same link |
| Debugging or auditing | Use `-WhatIf` first, then review the updated CSV and recovery report |
